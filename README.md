# Nix Media Server

This project provides a reusable, multi-site media server configuration using **NixOS**, featuring **Jellyfin**, **Audiobookshelf**, and **Caddy**.

Adding a new host? See the [Adding a new Host](#Adding%20a%20New%20Host).

***

## Features

*   **Jellyfin**: Free and open-source media system for managing and streaming video and music.
*   **Audiobookshelf**: Self-hosted audiobook and podcast server.
*   **Caddy**: Reverse proxy for Jellyfin and Audiobookshelf, with optional internal TLS.
*   **Configurable Media Paths**: Define root, music, video, and audiobook directories.
*   **SAMBA File Sharing**: Enable file sharing over SMB (for managing media files)
*   **OpenSSH**: Secure remote access.
*   **Declarative Configuration**: Manage your media server infrastructure with Nix Flakes.
*   **SOPS Nix**: Manage secrets securely with SOPS

***

## Configuration

The core media server configuration lives in:

    modules/media-server.nix

You can customize its behavior using these options:

*   `services.mediaServer.enable`  
    Enable or disable the entire media server stack. *(Default: `true`)*

*   `services.mediaServer.domainBase`  
    Base domain for Caddy vhosts (e.g., `jellyfin.yourdomain.com`).  
    *(Default: `media.ccistack.com`)*

*   `services.mediaServer.tlsMode`  
    TLS mode for Caddy:
    *   `"none"` → HTTP only
    *   `"internal"` → Caddy’s internal CA  
        *(Default: `"none"`)*

*   `services.mediaServer.paths`  
    Define media library paths:
        root       = /srv/media
        music      = /srv/media/music
        video      = /srv/media/video
        audiobooks = /srv/media/audiobooks

*   `services.mediaServer.audiobookshelf.enable`  
    Enable or disable Audiobookshelf container. *(Default: `true`)*

*   `services.mediaServer.jellyfin.enable`  
    Enable or disable Jellyfin service. *(Default: `true`)*

***

### Example Host Configuration

Each host has its own configuration under `hosts/`. For example:

    hosts/T29769/default.nix
    hosts/T29769/hardware.nix

*   `default.nix` → Site-specific settings (domain, toggles, etc.)
*   `hardware.nix` → Generated by `nixos-generate-config` for disks, bootloader, etc.

Common settings (hostname, timezone, SSH keys) live in:

    modules/common.nix

## Deployment

1.  **Clone the repository**:
    ```bash
    git clone https://github.com/<your-org>/nix-media-server.git
    cd nix-media-server
    ```

2.  **Create your host configuration**:
    ```bash
    mkdir hosts/my-server
    cp hosts/T29769/default.nix hosts/my-server/
    cp hosts/T29769/hardware.nix hosts/my-server/
    ```

3.  **Customize `flake.nix`**:  
    The flake auto-discovers hosts from `hosts/`.

4.  **Build and deploy**:
    ```bash
    nixos-rebuild switch --flake .#my-server
    ```

***

## Project Structure

*   `flake.nix` → Main Nix Flake entry point; defines system configs for each host.
*   `modules/media-server.nix` → Core module for Jellyfin, Audiobookshelf, Caddy.
*   `modules/common.nix` → Common system-wide settings.
*   `hosts/` → Host-specific configs:
    *   `hosts/<site>/default.nix` → Site-specific settings.
    *   `hosts/<site>/hardware.nix` → Hardware config.

## Secrets Management (sops-nix)

This project uses sops-nix for secrets management. Secrets are stored encrypted in `secrets/secrets.yaml` and decrypted at boot time on each host using SSH host keys.

### Getting Your Personal Editing Key

To edit secrets, you need your personal SSH key added to `.sops.yaml`. Run:

```bash
# Enter dev shell first
nix develop

# Convert your SSH key to age format
ssh-to-age -i ~/.ssh/id_ed25519.pub
# or
ssh-to-age -i ~/.ssh/id_rsa.pub
```

Add the output as `&admin` in `.sops.yaml`.


### Editing Secrets

```bash
# Enter dev shell
nix develop

# Edit secrets (decrypts, opens editor, re-encrypts on save)
sops secrets/secrets.yaml
```

The encrypted file can be safely committed to git.

### Verify Configuration

```bash
nix flake show
sudo nixos-rebuild switch --flake .#new-hostname
```

## Adding a New Host

1. **Copy an existing host configuration**:
   ```bash
   cp -r hosts/T29769 hosts/new-hostname
   ```

2. **Generate hardware configuration** for the new host:
   ```bash
   sudo nixos-generate-config --show-hardware-config > hosts/new-hostname/hardware.nix
   ```
    - This generated config might need a little cleanup but should include all the necessary hardware settings.

3. **Update `hosts/new-hostname/default.nix`** with the new hostname and settings.

4. **Add the host to sops-nix** (see Secrets Management below).

***

### Adding a New Host to Secrets

Each host needs its SSH host key added to `.sops.yaml` to decrypt secrets at boot time.

**1. Get the host's SSH host key (ed25519):**

Run on the new host:
```bash
sudo cat /etc/ssh/ssh_host_ed25519_key.pub | ssh-to-age
```

Or from your local machine:
```bash
ssh new-hostname "sudo cat /etc/ssh/ssh_host_ed25519_key.pub | ssh-to-age"
```

This outputs something like: `age1abc123...`

**2. Add the key to `.sops.yaml`:**

```yaml
keys:
  - &admin age1personal        # Your personal editing key
  - &t29769 age1T29769         # T29769 SSH host key (ed25519)
  - &p27691 age1p27691    # belmedia SSH host key (ed25519)
  - &newhost age1abc123       # NEW HOST - add this line

creation_rules:
  - path_regex: secrets/[^/]+\.yaml$
    key_groups:
      - age:
          - *admin
          - *t29769
          - *p27691
          - *newhost    # Add this reference
```

**3. Configure the host to use sops:**

In `hosts/new-hostname/default.nix`, add:
```nix
sops.age.sshKeyPaths = [ "/etc/ssh/ssh_host_ed25519_key" ];
sops.defaultSopsFile = ../../../secrets/secrets.yaml;
```

**4. Add secrets to the host (optional):**

```nix
sops.secrets.my_secret = {
  owner = "someuser";
  group = "somegroup";
  mode = "0400";
};
```

## One-Time Setup

Create media directories manually:

```bash
sudo mkdir -p /srv/media/{music,video,audiobooks}
sudo chown -R admin:media /srv/media
sudo chmod -R 775 /srv/media
``

sudo chmod 755 /srv/media/{music,video,audiobooks}
```

## Samba File Sharing (Optional Module)
If services.mediaServer.samba.enable = true; is set, the module automatically:

- Enables the Samba server
- Opens firewall ports
- Creates a share mapped to your media root directory

### Adding a Samba User
Samba users must exist as Linux users and also have a Samba password entry.

**Make sure the Admin user exists before adding a new SAMBA user**

**Add the user to Samba:**

```shell
sudo smbpasswd -a admin
sudo smbpasswd -e admin
```

The user can now authenticate when connecting to the share from Windows, macOS, or Linux.

Connecting to the Share
From another computer on your LAN:
\\hostname\media

or
smb://hostname/media

When you are asked for credentials, use the following information:

Username: admin
Password: [samba password set above]
Domain: Server Hostname

## GitOps Deployment with Comin

**Comin** is a pull-based deployment tool for NixOS. Each host runs a small agent that **polls your Git repo** and **automatically applies** the NixOS configuration associated with that machine (via flake outputs). It supports **testing branches per host**, **multi-remote polling**, and **safe deployments** you can roll back easily.  
**References:** Comin README & docs (features, quick start, module options). [\[github.com\]](https://github.com/matt1432/nixos-jellyfin), [\[discourse.nixos.org\]](https://discourse.nixos.org/t/new-flake-for-managing-your-jellyfin-server-declaratively/65379)

### Why use Comin here?

*   **Hands-off deploys:** Push to Git; hosts pull and apply.
*   **Reproducible:** Flakes pin inputs; every change is versioned.
*   **Testing branches per host:** Trial changes on a sandbox, then promote.
*   **Rollbacks:** NixOS generations remain available; roll back at boot or with `--rollback`.  
    **References:** Comin announcement (pull-based design); NixOS rebuild behavior (switch/boot/test). [\[mynixos.com\]](https://mynixos.com/options/services.jellyfin), [\[nixos.wiki\]](https://nixos.wiki/wiki/Caddy)

***

### 1) Enable Comin on your host

- Comin polls GitHub for a host's configuration (based on hostname) and automatically detects changes on the **`main`** branch
- Comin will **switch** to the `main` branch build and activate it (depending on your Comin config).  
**References:** Comin testing branch behavior; NixOS rebuild modes. [\[mynixos.com\]](https://mynixos.com/options/services.caddy), [\[nixos.wiki\]](https://nixos.wiki/wiki/Caddy)

### 2) Testing workflow (per-host)

Use a **`testing-<hostname>`** branch to try changes on your sandbox host before promoting to `main`.

1.  Create and rebase a testing branch:
    ```bash
    git checkout -b testing-[hostname]
    git rebase main
    git push origin testing-[hostname]
    ```

2.  Comin on `[hostname]` detects `testing-[hostname]` and runs:
        nixos-rebuild test
    (i.e., **`switch-to-configuration test`**). This **activates** the config without changing the bootloader.  
    **Reference:** Comin “How to test a NixOS configuration change”. [\[mynixos.com\]](https://mynixos.com/options/services.caddy)

3.  Verify on the host:
    ```bash
    sudo journalctl -u comin -n 200 --no-pager
    sudo systemctl status jellyfin caddy
    ```

4.  Promote to production (`main`) when satisfied:
    ```bash
    git checkout main
    git rebase testing-T29769
    git push origin main
    ```
